## 一、项目是什么

中国旅游规划 Web 应用：一张中国地图 → 选城市/景区/环线 → AI 口碑卡（避雷共识/暗广过滤/信任度）→ 两种行程模式生成多套方案。

- **城市模式**：选城市 → 出发地+总天数 → 「获取推荐」分配每城几天与起始城市 → 生成（时段规划、同片区聚类、跨城交通、返程预留）
- **自驾模式**：以景点为单位的跨城路线，2-opt 消除交叉，闭环返回

技术栈：**FastAPI + SQLite**（`backend/app/`）、**vanilla JS + ECharts 5.6**（`frontend/`）、**DeepSeek API**（`deepseek-chat`，带启发式 mock 兜底，无 key 也能全流程演示）。

数据规模：644 景点、180+ 城市、美食 648、住宿 150、平替 20+、环线 5 条（甘南/川西/青甘/滇西北/北疆）。

## 三、评价采集框架（喂数据即出 AI 口碑卡）★ 本次重点交付

> 已封装为可复用技能 **`skills/summarize-reviews/`**（`SKILL.md` + 独立 `summarize.py`，
> 不依赖应用、任何环境可跑）：原始攻略/点评文本 → 分类 → 暗广识别 → 避雷共识 → 信任度 → 口碑卡 JSON。
> 应用内接入走下方框架，纯文本总结直接跑技能脚本。

核心思想：**任何来源的信息，按标准结构喂进来，自动去重/分类/重算口碑卡**，不用写管线代码。

文件：
- `backend/collector/review_source.py` — 框架本体
- `scripts/import_reviews.py` — 命令行工具
- `POST /api/spots/{id}/reviews` — 应用内用户评价接口（P2 自产口碑）

**item 标准结构**：
```python
{
  "type": "guide"|"avoid"|"mixed"|""(空=自动分类),
  "title": "标题",
  "content": "正文(必须有,评分条目可无)",
  "author": "昵称(自动匿名哈希)",
  "source": "mafengwo|ctrip|dianping|amap|baidu|xhs|user",
  "url": "来源链接(去重键;无则用内容哈希)",
  "score": 4.6 | None,           # 官方聚合评分
  "comment_count": 21000 | None, # 评论数/热度
}
```

**用法**：
```powershell
# 1. 手工粘贴任意文本(最常用;网页复制/自己写的评价都行)
.venv\Scripts\python.exe scripts\import_reviews.py --spot 故宫 --source mafengwo --text "排队2小时门票60,值得但人多"

# 2. 批量文件(每行一条;支持 [avoid] 前缀 或 `标题 | 内容`)
.venv\Scripts\python.exe scripts\import_reviews.py --spot 玉龙雪山 --file reviews.txt

# 3. 高德/百度官方评分(需对应 key)
.venv\Scripts\python.exe scripts\import_reviews.py --spot 故宫 --source amap --score 4.6

# 4. 查看还没有真实笔记的景点(供采集)
.venv\Scripts\python.exe scripts\import_reviews.py --missing

# 5. 应用内用户评价
POST /api/spots/{id}/reviews  {"content": "...", "title": "..."}
```

**接入新来源**：实现一个 `ReviewSource.fetch(spot) -> list[item]` 子类即可。
内置来源状态：
| 来源 | 状态 |
|---|---|
| paste | ✅ 通用，任意文本 |
| amap / baidu | ✅ 评分接口已实现，填 key 即用 |
| xhs | ⚠️ 见 `scripts/collect_xhs.py --login`（需用户手动登录，滑块/限流是反爬难点） |
| mafengwo | ⚠️ 未自动抓取（加速乐 cookie 反爬）；建议复制文本走 paste |
| ctrip / dianping | ⚠️ 不建议自动抓取（反爬强+法律风险）；复制文本走 paste |

**AI 管线**：`backend/ai/pipeline.py` 的 `summarize_spot(spot_name, notes)` 产出口碑卡（高光/玩法/花费/暗广比例/避雷点/共识差评/信任度），LLM 优先 + 关键词兜底。

## 四、技术要点与坑（接手方必读）

1. **Windows 沙箱限制**（本机开发环境）：
   - 系统 curl/Schannel TLS 坏 → 用 Python urllib 发请求
   - pip 解包被拦 → `scripts/bootstrap_deps.py` 从清华镜像下载 wheel 手动解包
   - Playwright 启动浏览器需 `danger-full-access`；`PLAYWRIGHT_BROWSERS_PATH=.browsers`
2. **中文控制台乱码**：脚本开头加 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`
3. **ECharts 坑**：scatter 的 `symbol/symbolSize/label formatter` 回调签名是 `(value, params)`，`params.data` 才是数据项；同图混用不同 symbol 用**独立 series**，别用回调返回 symbol
4. **测试**：`pytest backend/tests`（91 个）。跑前删 `data/test_travel.db`（schema 变更）；`scripts/smoke_test.py` 前先清空购物车；`scripts/e2e_check.py` 需 Playwright 权限
5. **数据库**：`backend/app/db.py` 的 `init_db()` 用 ALTER TABLE 幂等补列；种子全是幂等 seed（`seed.py` + `seed_5a/4a/loops/popular/landmarks/museums...`）
6. **便携版构建**：`build_portable.py` 会自测（内置运行时导入 + 起服务验证）；改动后端后需重新打包
