# 评价/口碑数据源可行性评估（2024–2025）

> 目标：除了小红书（滑块风控受阻），评估从其他渠道获取真实用户评价/口碑的可行性，
> 并给出推荐实施路径。评估基于公开资料与 2024–2025 反爬现状。

## 一、分来源评级速览

| 来源 | 可取数据 | 评级 | 一句话理由 |
|---|---|---|---|
| 高德 Web服务 API | POI 元数据（名称/地址/电话/类型/部分营业时间） | **高** | 官方 API、需 key、免费配额够用、合法 |
| 高德 App 内点评 | — | **低/不可行** | 官方 API 无评分与点评字段；App 点评走私有接口，需逆向+登录+设备风控 |
| 百度地图 Place API | 评分 rating、评论数 comment_num | **中高** | 官方字段即含评分与评论数，无点评正文 |
| 马蜂窝 | 游记/攻略长文本 | **中** | 需过"加速乐"cookie 反爬（可无浏览器实现）；适合做攻略文本源 |
| 穷游 | 目的地信息/游记文本 | **中** | 反爬较弱，有成熟开源方案 |
| 携程 | 景点点评 | **低** | 需登录+动态 Cookie+滑块+签名，纯 requests 不可行，开放平台不含点评 |
| 去哪儿 | 点评 | **低** | 与携程同系，接口签名+风控 |
| 大众点评/美团 | 点评 | **不可行** | 动态字体加密+滑块+登录墙+账号风控，且法律风险最高 |
| 飞猪 | 点评 | **不可行** | 阿里系接口加密+淘宝风控+滑块 |
| TripAdvisor / Google Maps | 国外点评 | **低** | 官方 Content API 已关停；Google Places 正文仅 5 条且政策限制，国内景区覆盖差 |

## 二、关键结论

1. **高德（官方 API）**：`restapi.amap.com` POI 搜索/POI 2.0 返回名称、地址、经纬度、
   电话、类型及部分营业时间；**不含用户点评正文**，评分/评论数字段大多为空。
   元数据走官方 API = 高可行性；点评内容 = 放弃。
2. **百度地图 Place API**：官方接口直接返回 `rating` 与 `comment_num`，
   是唯一"官方合法拿聚合评分/热度"的渠道（中高）。
3. **携程/去哪儿**：点评需登录查看全部 + 动态 Cookie + 滑块 + 接口签名，
   2025 年仍有"破解动态 Cookies"的文章说明对抗持续升级；纯 urllib/requests 无解，
   开放平台面向商家分销、不开放点评。评级：低，不建议自建。
4. **大众点评/美团/飞猪**：动态字体加密（woff 每次变化）+ 滑块 + 登录墙 + 账号设备级风控；
   且这是法律重灾区——大众点评诉百度/爱帮、美团诉爬虫案均按《反不正当竞争法》高额判赔。
   评级：不可行。
5. **马蜂窝/穷游**：游记/攻略页可抓，马蜂窝主要障碍是"加速乐"cookie 反爬
   （JS 计算 cookie，可逆向后纯 requests 实现）；文本价值高，适合喂给 DeepSeek
   提炼口碑要点/避坑建议，而非结构化点评。评级：中。
6. **高可行性替代**：携程/飞猪开放平台均不开放点评；微信小程序不开放点评接口。
   最值得做的是 **应用内用户自产评价 + AI 整合**（合规、可控、长期），
   外加政务公开数据（文旅局、景区官网）与攻略文本提炼作补充。

## 三、推荐实施路径（本项目）

- **P0（1–2 天）**：高德官方 API 补元数据（电话/营业时间/类型）
  + 百度地图 Place API 拿「评分 + 评论数」聚合指标，纯官方合法。
  → 项目内已有 `backend/collector/amap_poi.py`（需 AMAP_KEY），可扩展。
- **P1（3–5 天）**：马蜂窝/穷游攻略文本采集（处理 cookie 反爬），
  DeepSeek 提炼口碑要点，绕开结构化点评难题。
- **P2（长期核心）**：应用内自产评价 + AI 整合，作为口碑主源。
- **P3（不建议自建）**：携程、大众点评、飞猪点评爬虫——反爬与法律成本远超收益。

## 四、合规风险提示

- 评论正文、用户昵称属个人信息，抓取与商用须获授权（《个人信息保护法》）。
- 携程/大众点评用户协议明确禁止爬取，已有《反不正当竞争法》高额判赔先例。
- 高德/百度/Google 开发者条款限制数据缓存、转售与展示方式。
- 建议：仅用官方 API 聚合指标，不存储评论正文与用户信息，控制 QPS，商用前做法律审查。
